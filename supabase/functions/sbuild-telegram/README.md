# Telegram Edge Function

Ця версія відповідає контракту клієнта S-BUILD Control
`POST /functions/v1/sbuild-telegram?action=send`, `?action=setup` і приймає
вебхуки Telegram через той самий шлях. Робочий сервер та Telegram під час
розробки не змінювалися.

Функція використовує системні секрети Supabase `SUPABASE_URL`,
`SUPABASE_ANON_KEY` і `SUPABASE_SERVICE_ROLE_KEY`, а також
`TELEGRAM_BOT_TOKEN`. Якщо задано `TELEGRAM_WEBHOOK_SECRET`, вебхук потрібно
налаштувати з цим самим секретом. Якщо змінну пропущено, функція перевіряє
наявний секрет на основі SHA-256 токена. Жодних значень секретів у репозиторії
не потрібно.

Для підготовки до розгортання потрібен ізольований Supabase зі схемою
S-BUILD Control і міграцією
`20261127231500_reconcile_telegram_delivery.sql`. Розгортання має зберегти
поточний режим `verify_jwt = false`, щоб Telegram міг викликати вебхук.
Функція перевіряє JWT та активну роль власника для клієнтських дій, окремо
перевіряє підпис вебхуку й зберігає сумісність з наявними одноразовими
службовими ключами.

Запустити локальні тести без мережі можна так.

```sh
node --test tests/telegram-edge.test.mjs
```

Невизначений результат відправлення зберігається як `uncertain`.
Обробник не надсилає повідомлення повторно з цього стану. Для виходу з
нього адміністратор має звірити фактичне повідомлення та запис доставки
в ізольованому середовищі. Повтор після підтвердженої відмови Telegram
отримує нове право відправлення. Вкладення надсилаються після фіксації
основного повідомлення, а помилка вкладення не повторює основне
повідомлення.
