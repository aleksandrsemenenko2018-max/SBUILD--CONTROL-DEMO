# Очередь задач Codex

GitHub Issues хранит задачи. Для передачи конкретного задания владелец проверяет текст в `.github/codex/tasks/<номер>.md`, сохраняет его в ветке `work`, ставит открытому Issue метку `codex-approved` и вручную запускает **Codex issue dispatch** с номером. Для Issue №1 подготовлена проверка регрессий авторизации. Содержимое Issue и комментарии остаются в GitHub. Codex получает проверенный текст из версии кода, выбранной при запуске.

Workflow проверяет владельца, ветку, Issue и историю запусков. Он разрешает один активный запуск и до трёх ручных запусков за скользящие 24 часа, включая неудачные и отменённые. Повторный запуск через **Re-run jobs** отклоняется. После допуска выполняется локальный набор модульных тестов. При включённой интеграции официальный Codex Action выполняет проверку в режиме чтения до пяти минут. Отчёт доступен в артефакте запуска семь дней. GitHub-токен имеет права чтения. Workflow не создаёт коммиты, комментарии и PR.

## Подготовка владельцем

1. Зарегистрируйте workflow в ветке по умолчанию через обычное ревью. GitHub требует этого для `workflow_dispatch`. Сам запуск выбирает ветку `work`.
2. Перед подключением создайте защищённое окружение `sbuild-codex` с обязательным ревью и разрешите для него только ветку `work`. Защитите изменения в workflow и файлах задач проверкой владельцем.
3. После явного разрешения расходов добавьте в окружение отдельный ключ проекта OpenAI `SBUILD_CODEX_API_KEY` с лимитами со стороны поставщика и установите переменную репозитория `SBUILD_CODEX_ENABLED=true` и укажите проверенный полный SHA рабочего коммита в `SBUILD_CODEX_APPROVED_SHA`. Для запуска на новом коммите сначала обновите проверенный SHA. Временной лимит и число запусков ограничивают использование, но сами по себе не задают денежный потолок API. Для остановки отключите переменную или отзовите ключ.
